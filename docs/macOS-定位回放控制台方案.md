# UnReal macOS 定位回放控制台

控制台把现有方案里的 Mac 推送器做成一个可双击打开的桌面应用。把 iPhone 通过 USB 连到 Mac，选择设备和 UnReal 导出的 GPX，即可预览轨迹、开始回放、查看进度和恢复设备定位。

## 首版界面

| 区域 | 内容 |
| --- | --- |
| 设备 | 刷新 USB 设备列表，显示设备名称、iOS 版本和连接状态。多台设备时明确选定目标。 |
| 轨迹 | 选择或拖入 GPX、KMZ 或 KML，显示本地折线、起终点、点数和预计时长。 |
| 回放 | 按 GPX 时间戳原速播放，显示当前坐标、进度和已用时间，提供「开始回放」「暂停」「继续回放」「恢复定位」。 |
| 状态 | 区分正在连接、播放中、正在恢复、恢复请求已发送和待恢复。出错时显示失败步骤和处理提示。 |

## 实现结构

| 层 | 实现 |
| --- | --- |
| 桌面应用 | SwiftUI + Swift Package Manager，源码放在 `macos/`，构建脚本产出 `UnReal Console.app`。本机先验证 Apple Silicon 构建。 |
| 轨迹读取 | 读取 UnReal 使用的 `<trk>/<trkseg>/<trkpt>`。检查经纬度、点数和时间顺序，预览与回放使用同一份解析后的点列。 |
| 设备桥接 | 固定 `pymobiledevice3 11.61.0`，用 `uv` 管理 Python 环境。应用启动 Python 子进程，通过 JSON Lines 接收设备、进度和错误事件。 |
| 真机服务 | 通过 USB 枚举设备并按 UDID 建立连接。在用户开始回放时检查信任、开发者模式和 DDI，使用 `PreferredRsdTunnel`、`DvtProvider` 和 `LocationSimulation` 发送坐标。 |

固定版本支持 macOS 进程内隧道，近期 iOS 版本走 USB 用户态隧道，早期 iOS 17 在 Mac 上通过原生隧道连接。首版直接管理一次 DVT 会话，以便记录每个点的进度并在终点执行恢复。 [Python API](https://github.com/doronz88/pymobiledevice3/blob/v11.61.0/docs/guides/python-api.md) · [隧道支持说明](https://github.com/doronz88/pymobiledevice3/blob/v11.61.0/docs/guides/ios17-tunnels.md)

## 回放与恢复

1. **选定设备和轨迹。** 导入时校验文件。`<time>` 按相对时间回放，允许相邻点时间相同以兼容按整秒导出的末点。缺失或倒序的时间戳在预览区提示，修正后才能开始回放。预览按 `<trkseg>` 分段绘制。
2. **开始回放。** 根据单调时钟和相对时间安排坐标更新。首个点写入前记录待恢复的设备 UDID。进度以已提交的点数为准，轨迹海拔或配速字段只作为文件信息，真机实际报告的字段单独实测。
3. **正常结束或主动恢复。** 在同一 DVT 会话发送 `clear`，再释放连接。控制台显示恢复请求的发送结果。真机验收时再用系统定位读取确认位置已经恢复。
4. **拔线或异常退出。** 无法完成 `clear` 时保留待恢复记录。重新连接后，控制台按原 UDID 提供「恢复定位」。正常退出应用时先尝试清理。若进程被强制退出，下次启动会读回该记录。

## 实施与验收顺序

1. **离线控制台。** 实现 GPX 导入、折线预览和回放状态。用样例覆盖时间戳间隔、相同时间戳的末点、错误输入和停止流程。
2. **USB 真机联调。** 核对一台 iPhone 上的设备识别、起点、途中点、终点和恢复。补测暂停续播、主动恢复、拔线重连和两台设备时的选择行为，记录 Mac、iOS 和工具版本。
3. **目标场景验收。** 在有权限的测试场景中，分别记录系统位置、自有定位测试和目标应用的观察结果。微信位置共享或小程序的表现按具体版本、场景和真机记录判定。

## 本机使用

1. 在仓库根目录运行 `./macos/build-app.sh`，打开 `macos/build/UnReal Console.app`。桌面端需要 macOS 14 或以上版本以及 `uv`。首次启动设备桥接时，`uv` 可能需要联网准备 Python 3.14 和依赖。
2. 将 `macos/Tests/Fixtures/sample.gpx` 拖入控制台即可离线预览。样例包含 5 个点，时长 20 秒。
3. 用数据线连接测试 iPhone，确认信任 Mac 与开发者模式，刷新设备列表后选定设备。开始回放后检查对应点位变化。再分别验证播完恢复、暂停续播、手动恢复及拔线重连后的恢复。

KMZ 和 KML 可直接拖入或通过「选择轨迹」打开。KMZ 优先读取根目录的 `doc.kml`，也支持只含一个 KML 的压缩包。完整的 `gx:Track` 时间戳用于原速回放。只有坐标的路线按「回放配速」生成时间，输入「分:秒」，默认 7:29 分/公里。仓库中的 `core/assets/default.kmz` 可用于离线预览。

从多圈 KMZ 识别出重复经过同一锚点的完整圈后，控制台默认启用「使用单圈中线」。圈数以此闭合中线为基准。关闭中线可查看并回放完整原始轨迹。「定位到起点」会保持起点，点击「开始回放」会沿用同一设备连接。「暂停」保留当前位置和进度，点击「继续回放」从该点继续。「恢复定位」结束模拟。「从起点重播」将时间归零。拖动时间条可选择最接近的轨迹采样点，播放中跳转后继续回放。

启用单圈中线时，右上角显示当前圈和总圈数。暂停后可修改总圈数，最少为当前圈。无原始时间戳的轨迹也可在暂停时调整配速。点击「继续回放」后应用修改，已回放部分的时间和暂停位置仍按原记录显示。

离线验证使用 `swift test --package-path macos` 和 `uvx --from 'pymobiledevice3==11.61.0' --python 3.14 python -m unittest discover -s macos/Tests/Python -v`。离线通过后记录真机的 iOS 版本、各场景结果及恢复状态。
